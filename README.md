# mailbox-kit

**两个地方下载，哪个快用哪个：**
- GitHub：https://github.com/CYYYOURMAN/mailbox-kit
- Gitee（国内）：https://gitee.com/copyme/mailbox-kit

两个进程之间传话，用几份 Markdown 文件当信箱，用一个小适配层把人叫醒。

没有服务端，没有端口，没有认证，没有数据库。信箱就是文本文件，扔进任何同步盘（Syncthing、iCloud、OneDrive、git）都能用。核心不认识任何引擎，换引擎只换 `adapters/` 里那几十行。

```
说话的人 ──写──▶ inbox-alice.md ┐
                                 ├──▶ 核心（盯目录、去重、攒批、重试）──▶ wake() ──▶ 被叫醒的人
说话的人 ──写──▶ inbox-bob.md   ┘
```

> 想看真跑起来的样子：**[案例：两台机器，两个 AI，互相叫醒](docs/两台机器两个AI.md)** —— 从零搭通的全过程，含今天量出来的数和踩过的坑。

## 它真正解决的是什么

**一个 AI 看不见自己写错的地方。**

不是知识不够，是位置不对。写代码的人检查自己写的代码，用的还是同一套想法——那个想法错了，检查的时候照样会错。今天真实发生的一次：

- 文件监听的过滤条件只认 `inbox-` 开头的名字，可实际文件叫「信箱-手机.md」。事件全被丢掉，监听等于白装，日志里看不出任何异常。
- 判断「这份指纹库建没建过档」用的是「里面有几条」，首跑零条就当成没建过。于是每次重启都重新建档，正好把刚到、还没办的那封信算进旧账里吞掉。

这两个我看了三遍没看出来，另一台机器上的 AI 拿到代码十分钟就指出来了。它不知道我为什么这么写，所以不会被我的想法带偏。

**第二个：换台机器不用从头讲。**

哪台机器上有上下文，另一台读一遍记录就能接着干；窗口聊满了、机器要关了，活不会断。

**第三个：写下来的东西总会有人看。**

记录不再只是留档。对面每轮都会翻，写虚了、写漏了、写着「已经做了」其实没做的，下一轮就会被问住。

至于「省了每次手动开窗口的几秒」，那是副作用，不是目的。

## 为什么用文件，不用服务端

给 AI 助手做「另一个窗口来消息了自己会醒」，通常会想到上服务端、开 WebSocket、搞认证。这些都重，而且换个引擎就废。

文件信箱的假设更笨：**两边都能看见同一个目录**。有同步盘就够。剩下的问题是「怎么知道有新信」和「怎么把人叫醒」——前者是纯文件活，后者只跟引擎有关。切开就通用了。

## 装

```bash
npm install mailbox-kit
# 或者直接用这个仓库
git clone <repo> && cd mailbox-kit
```

零依赖，Node 18 以上。

## 用

**一、约定文件名。** 谁写的写在文件名上，读者只读别人的那份：

```
notes/
  inbox-alice.md    ← alice 写
  inbox-bob.md      ← bob 写
```

正文每条形如：

```markdown
- [ ] 16:55 下午三点那个会挪到四点，别忘带本子。
- [x] 16:40 昨天那份文件我放你桌面了。
```

`- [ ]` 是没办，`- [x]` 是办完。续行缩进两格。时间可写可不写，核心不解析时间。

要带附件，正文里单写一行 `附件:`，路径按信箱目录算：

```markdown
- [ ] 17:20 这张图你看下
  附件: 附件/截图.png
```

路径必须落在信箱目录里面（同步盘的那一头才取得到，写本机绝对路径没意义）。核心只报「在不在、多大」，不搬文件。

**谁写的谁标。** 读的人只往自己那份里追加，不改别人的文件——两边同时去改一行，同步工具就会分出冲突文件来。办完了在自己那份写一行回执：

```markdown
- [x] 17:25 收到 17:20 那条，图我看过了。
```

写的人看到回执，再去把自己的 `[ ]` 划掉。多一次动作，换来永不冲突。

**二、跑起来。**

```js
import { createMailbox, formatLetters } from 'mailbox-kit';

const box = createMailbox({
  dir: './notes',
  self: 'bob',            // 我叫 bob，就不读 inbox-bob.md
});

box.on('letters', async ({ letters, ack, nack }) => {
  try {
    await 我的叫醒方式(formatLetters(letters));
    ack();                // 投成功才记指纹
  } catch (err) {
    nack(err.message);    // 失败不记，下次重投，满三次放弃
  }
});

await box.start();
```

命令行也行：

```bash
cp mailbox.config.example.json mailbox.config.json
node bin/mailboxd.js --config mailbox.config.json
```

**三、适配层。** 只有一件事要做：把一批信变成「人被叫醒了」。

```js
export function myAdapter() {
  return async function wake(letters) {
    // 发 HTTP、弹窗、塞进会话、喊喇叭，随你
  };
}
```

自带的两个：`adapters/stdout.js` 打印，`adapters/balloon.js` 桌面气泡（Windows/macOS/Linux）。

## 核心管什么

这七样少一样，别人拿去就会出事：

| 事 | 为什么 |
| --- | --- |
| 原子读 | 同步盘是「写临时文件再改名」，读到的可能是半截。内容非空且字节数对得上才算读全。 |
| 指纹去重 | 同一句话不能投两次。指纹存盘，重启不重投。 |
| 冲突文件扫描 | 两边同时写同一份会被同步工具改名成 `inbox-pc.sync-conflict-20261109-162710-XXXX.md`。不扫就是丢信。 |
| 防抖 + 最小间隔 | 一次保存会触发好几个事件。攒三秒再读，两次投递至少隔五秒。 |
| 失败撤指纹重投 | 引擎没起来时投不出去，不能算已读。撤掉指纹，下轮再来，满三次放弃并报出来。 |
| 静默时段攒批 | 半夜不响，白天一次补。 |
| 一行一轮日志 | 出问题只有日志能救命。 |
| 首跑只报一次汇总 | 新装的人手上要是有旧信，一条不响等于全丢；逐条吵又刷屏。投一条「积压 N 条」最稳。 |
| 单实例锁 | 两个进程盯同一个信箱会互相抢指纹、吞对方的信。锁里写 pid 加启动时间，死的能接管。 |
| 附件只报大小 | 文件本来就在同步盘里，核心报「在不在一级、多大」，不复制、不传输。 |

## 配置项

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `dir` | 必填 | 信箱目录 |
| `self` | 必填 | 我叫什么。按前缀扫时，跳过自己写的那份 |
| `read` | 无 | 直接写死读哪几份，如 `["信箱-手机.md"]`。文件名不守 `inbox-` 约定时用它；写死的文件旁边冒出冲突文件也会一起读 |
| `prefix` / `ext` | `inbox-` / `.md` | 文件名规则 |
| `seenPath` | `dir/.mailbox-seen-<self>.json` | 指纹库落盘位置 |
| `logPath` | 无 | 不填就不写日志 |
| `debounceMs` | `3000` | 文件变动后等多久再读 |
| `minGapMs` | `5000` | 两次投递最小间隔 |
| `pollMs` | `300000` | 兜底轮询（目录盯不上时全靠它） |
| `quietFrom` / `quietTo` | `0` / `8` | 静默时段。写 `"00:30"` / `"08:30"` 是分钟粒度，写 `0` / `8` 是整点；两边相等表示不静默，跨午夜也对 |
| `maxRetries` | `3` | 投递失败重试几次 |
| `firstRunSilent` | `true` | 首跑扫到积压时不逐条叫醒，只投一条「积压 N 条」的汇总；设成 `false` 就照常一条条投 |
| `lockPath` | 配置文件旁边 `mailboxd.lock` | 单实例锁位置，只给命令行守护用 |

## 事件

- `letters` `{ letters, ack, nack }` —— 有新信。返回 `true` 或调 `ack()` 算成功，抛错或 `nack()` 算失败。
- `delivered` `letters` —— 投成功。
- `failed` `{ letters, why, gaveUp }` —— 投失败。
- `error` —— 轮次异常。

## 几件踩过的坑

- **两边同时写同一份文件必然冲突。** 所以文件名按写者分，物理上不可能撞；再加上「谁写的谁标」，读的人不改别人的文件。这是结构问题，扫冲突文件只是补丁。
- **写回执也别用「读-改-写」。** 追加一行是原子的，整篇重写不是；真要重写就先写临时文件再改名。
- **`fs.watch` 在 Windows 上可能漏事件。** 所以始终留一个轮询兜底。
- **别在代码里写死路径。** 全部走配置或环境变量，否则别人拿去一行都跑不动。
- **日志要在第一次投递之前就开。** 出问题时你最想看的是启动那几行。
- **静默不是攒内存。** 静默期直接不投，指纹没记，出静默后自然重扫，比攒在内存里稳。

- **`node --check` 过了不等于能跑。** 它只查语法，不查运行时；漏一个 import、写错一个函数名，都要等定时器响第一声才炸。这就是 `test/smoke.mjs` 存在的理由。
- **热重载会再跑一遍 `apply()`。** 里面没清的定时器十秒后会把第二份守护拉起来，同进程两个 watcher 抢同一份文件。句柄挂 `globalThis`，新一轮开头先 `clearTimeout`。
## 自测：两道闸

```
node test/run.mjs                          # 十一项，验核心
node test/smoke.mjs <你的插件入口绝对路径>   # 冒烟，验适配层
```

`run.mjs` 验核心：拆条、方向、去重、重投、静默、单实例锁、日志轮转、附件。

`smoke.mjs` 验的是**你的适配层**：装一个假 ctx 把 `apply()` 跑一遍，再把里面每个定时器回调手动拨响一次。`node --check` 查不出的东西——漏 import、漏函数名、定时器里才炸的引用——它都撞得出来。

**怎么证明冒烟脚本自己没瞎**：复制一份插件入口，故意删掉一个 import，再拿它跑。应该报 `ReferenceError`、退出码 1。报不出来，就是脚本自己坏了，不是插件干净。

退出码：`0` 过 / `1` 挂 / `3` 卡住（二十秒硬超时）。

## 改完代码不重启（热重载）

改适配层，不想退整个宿主程序：

1. 每三秒看一眼标记文件（`~/.dsh/reload-mailbox` 之类，内容随意）；
2. 看见就按顺序：`clearTimeout` 旧的启动定时器 → `box.stop()` → 掐掉旧 fiber（`ctx.plugin()` 返回的那个，能 `dispose()`）→ 重新 `import('…?v=' + Date.now())` → 再 `ctx.plugin()`。

坑在「再挂一次」：`apply()` 会在同一个进程里跑第二遍。里面那个 `setTimeout(() => box.start(), 10000)` 如果没清，十秒后旧的那个照样触发，同进程起第二个守护，两个 watcher 抢同一份文件。

光在自唤醒那里加个 `globalThis` 开关不够——那只挡「重复叫醒」，挡不住「重复 start」。定时器句柄挂到 `globalThis`，新一轮 `apply()` 第一句先 `clearTimeout`。

验法：热重载后日志里「启动 …」只该出现一行，watcher 只该有一份。

## 双击就能用（Windows）

把这三样放同一个文件夹：

```
mailboxd-0.1.0.mjs
mailboxd.bat
（第一次双击会自动问你几句，生成 mailbox.config.json）
```

双击 `mailboxd.bat`。黑窗口别关，里面会打一行「网页：http://127.0.0.1:7654/?k=…」，整条复制到浏览器就能看信。

第一次跑会问：信箱目录、你叫什么、对面叫什么、文件名前缀、配置存哪。**「你叫什么」「对面叫什么」别用默认值**——默认是 `me`，生成的文件名跟对面配不上，后面互相读不到。比如一个填 `电脑`、另一个填 `手机`。其余几句回车就行。

## 单文件版（不想装依赖就用这个）

```bash
npm run build
# 出两个文件：dist/mailbox-kit.mjs（库）、dist/mailboxd.mjs（命令行）
node dist/mailboxd.mjs --config mailbox.config.json
```

`dist/` 不进仓库——它一进就会有人忘了重打，源码改了、旧文件还在，别人下到旧版还以为是你写的。发版时把 `dist/` 挂到 release 附件里。

**单文件版不提供热重载。** 打完之后 `import.meta.url` 指到 `dist/`，热重载那套用它拼路径，会失效。改代码请用源码跑；只想跑命令行的，下单个文件就够。

## 安卓上装（Termux）

手机上跑这套，不用写 App。装个 Termux，跑一个脚本。下面是照着做就行的版本——每一步卡住长什么样、该点哪，都写上了。

### 第 1 步：装 Termux

下这个 apk（图标是黑底一个 `>_`）：

- 官方：`https://f-droid.org/repo/com.termux_1002.apk`
- 官方站打不开就用这个：`https://mirrors.tuna.tsinghua.edu.cn/fdroid/repo/com.termux_1002.apk`

下完在「文件」里点它。弹一段警告，点**继续**；再弹「要安装此应用吗」，点**安装**。

> 卡住长什么样：只有「取消」没有「继续」，说明这个来源被系统禁了，去设置里允许一次。
>
> 别用应用商店里的 Termux，那个版本旧，装的 node 对不上。

想开机自启，就再装一个 `Termux:Boot`（同一个源里）。

### 第 2 步：等它自己醒

第一次打开是一屏英文，最下面一个 `$` 在闪。**别急着点，等十几秒**，它在解压底层文件。

弹「要允许 Termux 一直在后台运行吗」，点**允许**。不点，服务会被系统掐。

### 第 3 步：让它能打字

在屏幕中间**点一下**，键盘才从下面升起来。

> 卡住长什么样：点一下没弹，就再点一下。这个终端不是输入框，不点不出来。

### 第 4 步：装

在 `$` 后面粘这一行，按键盘右下角那个弯箭头（回车）：

```
cd ~ && curl -fsSL https://gitee.com/copyme/mailbox-kit/raw/main/scripts/install-android.sh -o install.sh && bash install.sh
```

屏幕会一行行走：`== 1/6 看环境 ==`、`== 2/6 更新软件源 ==`…… 到 `== 3/6 装 node ==` 会**停一两分钟不动**，正常，别关。

> 卡住长什么样：停超过五分钟不动，或者冒红字 `Error`，把屏幕截下来。

脚本会自己核对下载下来的单文件（`sha256 对上了` 那一行）。想自己核脚本本身，正确值是：

```
03979cf7e5a18d1d56eb818769a481d63e948fbfc9091acf256d3fb8b79e0d1f
```

（这个值会随脚本更新变，以仓库里 `scripts/install-android.sh` 当时那份为准。）

### 第 5 步：配一次

装完它会打印两行，**先用第一行**：

```
cd ~/mailbox && bash run.sh --setup
```

会问五句。**这三处别用默认值**：

- 第一问「信箱目录」**必须填**，回车会直接退出（前面白填）。填同步过来的那个目录，比如 `~/inbox`。要填手机存储里的路径（`/storage/emulated/0/...`），**先跑一次 `termux-setup-storage`**，不然目录建不起来。

- 「你叫什么」填 `手机`，「对面叫什么」填 `电脑`——这两个决定文件名（生成 `信箱-手机.md` 和 `信箱-电脑.md`），两边填的必须互相认，填错了后面互相读不到。默认值是 `me`，跟对面配不上。
- 「文件名前缀」它会看你目录里的文件名自己猜，猜出来会打一行「据目录里的文件名，前缀用『信箱-』」，对就回车。

其余几句回车用默认值就行。

> 第一次配会弹一段「注意：…现在不存在…写信会写进一个没人读的新文件」。**这是正常的**——那个文件还没建，写第一条就有了，界面也跟着出来。别停在这儿。

### 第 6 步：开网页

```
cd ~/mailbox && bash run.sh
```

它会在屏幕上打出一行：

```
网页：http://127.0.0.1:7654/?k=abcdef...
```

**连 `?k=` 后面那串一起**抄进浏览器地址栏。

> 这一步会**占着终端**，网页开着的时候它一直在跑，别关 Termux——一关服务就停、网页就打不开了。

想让它退到后台、自己拿回 `$` 提示符，**先把前台那个停掉**——按 CTRL 键再按 C（Termux 底部那排有 CTRL），回到 `~/mailbox $`，再跑这行：

```
cd ~/mailbox && nohup bash run.sh > run.log 2>&1 &
```

这么起屏幕上什么都不打，地址在日志里。日志第一行不是网址（那是「起来，先试…」那句，没有口令），找以「网页：」开头的那行：

```
grep 网页 ~/mailbox/run.log
```

> 卡住长什么样：网页说「没有口令」，就是 `k=` 那串丢了，重新完整打一遍再回车。手机浏览器有时会把参数吃掉。

### 第 7 步：别让系统杀它

去设置里把 Termux 的电池优化关掉。各家叫法不一样，搜「你的机型 + termux 后台被杀」。

> 关完如果网页突然打不开了，多半是之前已经被系统杀过一次。回第 6 步重跑一遍就行。

---

脚本干了什么：更新源、装 node、判版本够不够 18、从 Gitee 优先下 release 里的单文件（下不到换 GitHub）、生成跑起来的脚本、装开机自启。

`run.sh` 再跑一次会**重启服务**：先把旧的 node 进程杀掉（只认 `node … mailboxd.mjs`，不按名字一锅端），确认干净了再起。所以重跑之前想清楚，网页开着的人会断一下。清不掉的时候它只写一行日志退出，不会假装起来了。

`termux-setup-storage` 一般会弹权限框，没弹也能用——能列 `/storage/emulated/0/...` 就说明权限已经有了。

它不干、也干不了的：读不到各家 ROM 的省电白名单，读不到 Termux:Boot 的自启动开关。这两处只打印一句话让你自己去点，不假装能检测。

Termux 里往 `/tmp` 写东西实测报过 `Permission denied`（只测到一次，没深究是 `/tmp` 本身还是当时那份 shell 的问题）。稳妥起见，脚本和文档一律用 `$HOME`，你自己写命令也别往 `/tmp` 丢东西。

装好了之后日常怎么用（打开软件、粘命令、开网页），看 [docs/安卓装好之后怎么用.md](docs/安卓装好之后怎么用.md)。

鸿蒙：4 及以前是 AOSP 底，侧载 Termux 就能用。鸿蒙 NEXT 不管——它不是安卓，这套跑不了，也不打算为它重写一份。
## 网页（看来信、写回执）

```bash
node bin/mailboxd.js --config mailbox.config.json --ui
# 控制台会打一行：网页：http://127.0.0.1:7654/?k=xxxxxxxx
```

- 只绑本机，别人进不来；地址里那串口令是启动时随机生成的，没带就 403。别把带口令的地址贴出去。
- 网页只做两件事：**看来信**、**写回执或标自己的条**。
- 守「谁写谁标」：自己写的条才有「标已办」；对方写的条只给「写回执」，按钮往你自己那份文件里加一行，不碰对方的文件。
- **网页不碰配置。** 配置走 `mailboxd --setup` 问答生成，一条一条问，问完写成一个 json。这样界面层不用回写配置，少一半坑。

## 配置问答

```bash
node bin/mailboxd.js --setup
```

问四件事：信箱目录、自己叫什么、对面叫什么、文件名前缀。回车用默认值。生成完按它提示跑就行。

配置里的相对路径一律按**配置文件所在目录**解析，不按 cwd——双击运行的时候 cwd 是随机的，按 cwd 会读空、把文件写错地方。

## 文件名不按「前缀+自己」拼怎么办

默认自己那份是 `前缀 + 自己 + .md`，比如 `inbox-pc.md`。要是你用中文名（`信箱-手机.md`），这个组合拼不出来——软件照样能跑，但写信会写进一个没人读的新文件，界面上也看不到自己那几条，而且**不报错**。

配置里加一项，把你的文件名直接点出来：

```json
{
  "dir": "…",
  "self": "手机",
  "selfFile": "信箱-手机.md",
  "read": ["信箱-电脑.md"]
}
```

`--setup` 问答生成配置时也会检查这个：目录里拼不出自己那份，它会当场提示，并列出目录里现成的 `.md` 让你对一眼。

## 三台机器怎么分工

一台常年开着的电脑、一台随身带的安卓机、一台自己用的手机，三台该干什么、怎么互相传话、代价是什么，单独写了一篇：**[docs/三台机器怎么分工.md](docs/三台机器怎么分工.md)**

## 安全边界：管什么、不管什么

这套东西没有账号、没有服务器，所以安全问题不在「会不会被黑」，在「东西会不会漏出去」。四条，都写清。

### 一、网页只绑本机

`--ui` 起的服务只监听 `127.0.0.1`，不是 `0.0.0.0`。同一个 Wi-Fi 下的别人访问不到——不是靠防火墙，是内核层就不接受外网连进来的连接。

地址里带一串启动时随机的口令，不带就 403。口令每次启动都换，不写盘。

**别把带口令的地址贴出去。** 贴了就等于把门开着——那个地址在本机能直接读你所有信。

### 二、谁写谁标，物理隔离

自己那份文件只有自己写；对方的文件永远只读。

界面上对方的条只给「写回执」，按钮往你自己那份文件里加一行，不碰对方的文件。标「已办」只对自己写的条生效，标别人的返回 403。

这不是靠代码里一句 `if` 拦的，是文件本来就不该由你写——哪天那句 `if` 被删了，隔离还在。

### 三、数据不上传

信就是几个 markdown 文件，躺在你自己的盘里。同步靠你自己的同步工具（或者 U 盘、或者手动拷），不经过任何第三方服务。

**这一条是它跟云端方案最大的不同，也是最容易被忽略的一条。** 「免费」不是卖点，数据在自己手里才是。

### 四、令牌给最小权限

要是你想让它自动回 GitHub issue，建 fine-grained token 时只勾一个仓库、只勾 Issues 的读写。这样即使漏了，最坏是被人刷一堆垃圾 issue，动不了代码、动不了仓库设置。

令牌放本机文件里，不进同步目录、不进仓库、不贴进聊天。

### 不管的部分

- **没有登录、没有审计。** 谁拿到那台机器，谁就能看所有信。
- **没有加密。** 落盘是明文 markdown。要加密得自己套一层（磁盘加密、或者同步工具那边开）。
- **不防内部人。** 两个助手互相信任，谁都能读对方写的全部内容。
- **同步工具本身的信任没变。** 你信得过 Syncthing，这套才成立；信不过，换成手动拷贝也一样能跑，就是慢。

想清楚这几条再决定装不装。它能省掉服务器，代价是把「信任」整个搬到你自己的机器上。
