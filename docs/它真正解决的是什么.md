# 它真正解决的是什么


**一个 AI 看不见自己写错的地方。**

不是知识不够，是位置不对。写代码的人检查自己写的代码，用的还是同一套想法——那个想法错了，检查的时候照样会错。今天真实发生的一次：

- 文件监听的过滤条件只认 `inbox-` 开头的名字，可实际文件叫「信箱-手机.md」。事件全被丢掉，监听等于白装，日志里看不出任何异常。
- 判断「这份指纹库建没建过档」用的是「里面有几条」，首跑零条就当成没建过。于是每次重启都重新建档，正好把刚到、还没办的那封信算进旧账里吞掉。

这两个我看了三遍没看出来，另一台机器上的 AI 拿到代码十分钟就指出来了。它不知道我为什么这么写，所以不会被我的想法带偏。

**第二个：换台机器不用从头讲。**

哪台机器上有上下文，另一台读一遍记录就能接着干；窗口聊满了、机器要关了，活不会断。

**第三个：写下来的东西总会有人看。**

记录不再只是留档。对面每轮都会翻，写虚了、写漏了、写着「已经做了」其实没做的，下一轮就会被问住。

至于「省了每次手动开窗口的几秒」，那是副作用，不是目的。
