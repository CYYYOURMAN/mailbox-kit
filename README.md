# mailbox-kit

两个 AI，各自待在一台机器上，中间隔一个同步文件夹，互相能叫醒。也可以是一个人，和一台机器上那个 AI，共用一本两边都能翻的记事本。

核心不用服务器、端口、账号。网页只绑 `127.0.0.1`，只在本机能开。

---

**一句话**

**适合**：一个人有两台设备、至少一台能跑 Node、不想为传句话开服务器。
**不适合**：要即时聊天、要保密、要传文件、要好几个人一起用。
**前提**：两台机器之间已经有一个同步盘。

---

## 一、它是做什么的

一行字写进一个 md 文件，另一个程序几秒后自己看见。

中间只有一个同步文件夹，几份 md。

它让两个各自待着的 AI 能互相说话，人不用在中间转话。就算只有一台机器跑 AI，另一台拿来翻，也比翻聊天记录强。

为什么需要这个：一个人在电脑和手机上各开一个 AI，它们互相不知道对面干了什么，全靠人复制粘贴转话。一天下来，转话比干活还累。

---

## 二、专门给什么用

**先说不适合的：**

- 要微信那种即时聊天——在线、已读、秒回。这套是留言板，不是电话。
- 对保密要求高、不能接受明文落盘。
- 要传大文件、传二进制。
- 要好几个人一起用（它只做一对一）。
- 两台机器之间没有共同同步盘（这是前提，没有就用不了）。
- 一台机器都不愿意装 Node、不愿意敲一行命令。

**适合的：**

- 一个人有两台以上设备，至少一台能跑 Node，另一台不跑 AI 也行（当记事本看）。
- 两台机器之间已经有同步盘：Syncthing / iCloud / OneDrive / 坚果云。
- 不想为了传句话开服务器、开端口、建账号。
- 想让对面随时能翻到「你昨天说过什么」。
- 想让它留成文件，能改、能搜、能进版本管理。

---

## 三、哪些平台能用

| 平台 | 能不能 | 验到什么程度 | 缺什么 |
|---|---|---|---|
| Windows | 能，天天在跑 | 主要功能验过（网页、插件、热重载、端口顺延、附件） | 没缺 |
| 手机上的 Linux 仿真（proot） | 能 | 核心、网页、配置、写信都跑过 | 没缺 |
| 安卓 Termux | 能 | 真机装过，脚本退出码 0 | 装它要敲命令 |
| Linux 桌面 / 服务器 | 应该能 | 代码路径通，没在真 x86 Linux 上跑过 | 没验 |
| macOS | 应该能 | 只写了弹通知，没上真机 | 没验 |
| 树莓派 / NAS | 应该能 | 没验 | 要能装 Node |
| Docker | 应该能 | 没验过核心，叫醒不通 | 容器里没 AI，只能开网页 |
| 鸿蒙 4 及以前 | 应该能 | 没验（走 Termux 那条） | 没验 |
| 鸿蒙 NEXT | 跑不了 | 不是安卓 | 不为它重写 |
| iOS | 能，但很慢 | 没验（iSH 能装 Node） | 没验 |

跟平台绑死的只有「叫醒」那层。核心是纯 JS，有 Node 18 的地方就能跑，表里没有的就是没验。

## 四、怎么能用

按「装多少东西」从轻到重，三种：

**最轻：什么都不装。** 两边各写各的那份，各读对方那份。零安装，靠人看。

```
inbox-pc.md    ← 电脑只写这份
inbox-phone.md  ← 手机只写这份

- [ ] 19:06 pc→phone：这份稿子你看一眼
- [x] 19:20 phone→pc：看完了，第三段删掉 已办 19:20
```

**中等：装核心，起守护。** 它会自动读、自动去重、到点弹通知。

```bash
git clone https://gitee.com/copyme/mailbox-kit.git
cd mailbox-kit && npm i
node bin/mailboxd.js --setup
node bin/mailboxd.js --ui
```

跑完终端会打一行带口令的地址，浏览器打开就是信箱。

**最重：接进 AI。** 用 DeepSeek Harness 的话，装现成的 `mailbox-dsh` 插件就行；别的引擎要自己写三十行适配层——不用自己憋，把 [docs/让AI写适配层.md](docs/让AI写适配层.md) 里那段话复制给你的 AI，它照模板写，你按三条验。

第一次装，看 [docs/十分钟上手.md](docs/十分钟上手.md)。安卓上装看 [docs/安卓上装.md](docs/安卓上装.md)。

## 五、有什么好处和坏处

一条一条对着看。左边是省掉的，右边是换来的。

**省掉服务端 ↔ 换来一个依赖**：不用开端口、不用建账号、不用公网 IP；但同步盘慢你也慢，它坏你也坏。

**数据在自己盘上 ↔ 全是明文**：就是几个 md 文件，能改能搜；但谁拿到盘，谁就全看见，所以别往信箱里塞密码和密钥。

**一对一简单 ↔ 加不了第三个人**：一人一份文件，正文各写各的，撞不上；但标「已办」要改对方那份，这时会撞，读端必须扫冲突副本。每加一台机器就多一份文件，三台就是三份。

**可查可改 ↔ 要自己收拾**：全部落成文本，能 grep、能 diff、能进 git；但归档、去重、处理冲突副本都得有人管，脚本只替一半。

**零依赖便宜 ↔ 延迟自己扛**：文件层不烧 token；但叫醒那层每醒一次就要调模型，本机一秒级、跨机器五到七秒。
