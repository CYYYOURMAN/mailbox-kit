# 三台机器怎么分工

一个人手上往往不止一台设备：一台常年开着的电脑，一台随身带的安卓机，一台自己用的手机。三台都能装点东西，但没人说清哪台该干什么。

结果通常是：活全挤在一台上跑，那台一关全停；随身那台闲着，只用来刷视频；最贵那台反倒在等命令。

这里写的是一种分法，不是唯一解。

## 先说一条不好听的

**苹果手机当不了节点。** iOS 上跑不了常驻进程，也装不了这类插件。它只能是「指挥层」——你在上面发命令、看结果，活不在这台上干。

安卓可以，因为它能开个终端环境。安卓用户照着搭能跑通，苹果用户照着搭会卡在这一步，所以先说。

**角色可以合并，别硬凑三台。** 只有一台电脑的，常驻层和指挥层就是同一台；只有手机的，随身层自己扛。分层是为了说清「什么活该放哪」，不是让你去买设备。

## 一、分三层，按「能不能一直开着」和「离人多近」

不给设备名，给角色。

### 常驻层

一直开着，跑定时、跑采集、跑批处理。

- 特点：能等，不能断。
- 适合的活：半夜跑的巡检、要跑十几分钟的采集、需要慢慢攒的数据。
- 放哪：插着电、连着网、没人管也不会关机的那台。

### 随身层

跟着人走，接话、回评论、看消息。

- 特点：要快，能断。
- 适合的活：有人回你话了你得马上接、刷到值得回一句的、临时想起要查一件事。
- 放哪：你随身带的那台手机。

### 指挥层

你自己用的那台。只发命令、看结果，不干活。

- 特点：什么都不用装，能打字就行。
- 适合的活：说「去把那个弄了」、点头或者摇头、看它做完了没有。
- 放哪：你最常用、最不想折腾的那台。

指挥层最省电、最不容易坏，因为它上面什么都没有，只负责说话。

## 二、三层之间靠什么传

不架服务器、不开端口、不要公网 IP。用一个双向同步的文件夹。

### 文件名按写者分

- 常驻层写 `信箱-电脑.md`，随身层读；
- 随身层写 `信箱-手机.md`，常驻层读；
- 指挥层不写文件，它在聊天里说，由其中一层代写成条。

**同一份文件只许一个人写。** 这不是洁癖，是必须——两个人同时写，同步盘会判冲突，把其中一份顶成 `xxx.sync-conflict-日期-随机.md`，读端不认识那个名字，那封信就静默丢了。真丢过。

### 一行的格式

```
- [ ] 20:10 电脑→手机：采集跑完了，草稿在 notes 里，你扫一眼
```

`[ ]` 没办、`[x]` 已办。谁写的谁标，读的人不改别人的文件。

### 靠什么叫醒

文件落盘不会自己叫人。得有个守护盯着目录：看见自己该读的那份有新行，去重、攒批、把文字塞给那台机器上的助手，让它醒过来接着干。

这一步是整条链里唯一需要针对不同助手各写一遍的地方——接口不一样，但干的事就三件：拿到会话、把文字塞进去、看它醒没醒。三十行左右。

## 三、一整天怎么跑

按时间走一遍真实的流水。

**夜里（便宜时段）**：常驻层跑巡检、采数据、把第二天要发的东西起草好，写进待发文件。它不等回复，跑完就写记录。

**早上**：人起来看草稿，点头或者改。改一句就写一句进记录，不攒。

**白天**：随身层接话、回评论。要发的先念给人听，人点头才发——这一步不能省，自主发和有把关的发，出事时的代价差很远。

**随时**：指挥层在聊天里插一句，哪一层收到就哪一层办。干活的那层在跑长任务时，另一个人说话照样能接——活是后台跑的，话是当场接的。

**晚上**：两头各写一份记录，只追加不重写。第二天谁接着干，翻对方的记录尾巴就知道它刚做了什么。

## 四、这么分的好处

**一、干活不影响聊天。** 常驻层跑重活的时候，人还能跟助手说话。这一点比「省时间」实在——大多数人怕的就是「一跑起来就不能用了」。

**二、从 0 到 1 是说着说着就出来的。** 不是先画架构图再动手，是一部手机上一条一条说，边说边改，几个钟头从「换个说话方式」变成别人能装的包。计划赶不上改。

**三、零基础也能干。** 会打字、能说清自己要什么，就能推着走。不用先学命令行，不用先懂协议。真正要懂的东西会在卡住的时候自己撞上来，那时候学得最快。

**四、每件事都留了字。** 换台机器接手不用从头讲，翻记录就行。这条在只有一个人的时候看不出价值，等两头都开始干活的时候就显出来了——两边的助手能互相读对方写的记录，不用人转话。

## 五、代价，也写清

**一、多一层就多一处会坏。** 三层里任何一层没配好，整条链断在那儿，而且断的时候没声音——信写进去了，没人读，谁也不知道。

**二、跨机传话是秒级，不是毫秒级。** 同步盘那边还有一层自己的等待。想再快，得去调它的监听延迟，但调太快容易读到写了一半的文件。

**三、这套靠的是「自觉」。** 没有调度中心，没有重试队列，一层没醒，那条信就一直躺着。所以得有个兜底：定时轮询，加上「投失败了要说一声」。

**四、大厂在做同一件事。** Google 的 A2A 那套协议，目标是让不同厂商的助手互相说话。真做通了，这种拿文件夹传话的土办法会被顺手替换掉——就像有了快递，没人再托邻居带东西。

**五、免费不是护城河。** 这套不收费，因为它本来就没有收费的地方。但开源的东西被大厂顺手吸收的例子太多了，用户最终挑的不是「不要钱」，是「不用配就能用」。

真到那天，它的活路不是比谁便宜，是**大厂管不到的地方它还在**：两个人不在一个网里、谁都不想把手上的东西交给第三方、只想让两台自己的机器说话。

## 六、别人照着搭要注意

- **设备不齐就合并角色**，别为了「三台」去买设备。
- **适配层要自己写**，三十行，干三件事。没有这一步，文件写得再整齐也没人醒。
- **别把配置发出去。** 配置里有路径、有账号、有令牌。发结构可以，发值等于把钥匙挂门口。
- **先跑通一遍再改。** 这套东西坏起来不报错，只静默不干活——先有一条能走通的链，再往上加东西。

---

一句话总结：**把活按「能不能一直开着」和「离人多近」分开，用一个文件夹把它们串起来，让每件事都留下字。**
