# 自测与热重载


```
node test/run.mjs                          # 十一项，验核心
node test/smoke.mjs <你的插件入口绝对路径>   # 冒烟，验适配层
```

`run.mjs` 验核心：拆条、方向、去重、重投、静默、单实例锁、日志轮转、附件。

`smoke.mjs` 验的是**你的适配层**：装一个假 ctx 把 `apply()` 跑一遍，再把里面每个定时器回调手动拨响一次。`node --check` 查不出的东西——漏 import、漏函数名、定时器里才炸的引用——它都撞得出来。

**怎么证明冒烟脚本自己没瞎**：复制一份插件入口，故意删掉一个 import，再拿它跑。应该报 `ReferenceError`、退出码 1。报不出来，就是脚本自己坏了，不是插件干净。

退出码：`0` 过 / `1` 挂 / `3` 卡住（二十秒硬超时）。


## 改完代码不重启（热重载）

改适配层，不想退整个宿主程序：

1. 每三秒看一眼标记文件（`~/.dsh/reload-mailbox` 之类，内容随意）；
2. 看见就按顺序：`clearTimeout` 旧的启动定时器 → `box.stop()` → 掐掉旧 fiber（`ctx.plugin()` 返回的那个，能 `dispose()`）→ 重新 `import('…?v=' + Date.now())` → 再 `ctx.plugin()`。

坑在「再挂一次」：`apply()` 会在同一个进程里跑第二遍。里面那个 `setTimeout(() => box.start(), 10000)` 如果没清，十秒后旧的那个照样触发，同进程起第二个守护，两个 watcher 抢同一份文件。

光在自唤醒那里加个 `globalThis` 开关不够——那只挡「重复叫醒」，挡不住「重复 start」。定时器句柄挂到 `globalThis`，新一轮 `apply()` 第一句先 `clearTimeout`。

验法：热重载后日志里「启动 …」只该出现一行，watcher 只该有一份。
