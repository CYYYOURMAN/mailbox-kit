# 让 AI 帮你写适配层

`mailbox-kit` 的核心不认识任何 AI 引擎。要让它把一个引擎叫醒，得写一层薄的适配——通常三十行左右。

这三十行不用你自己憋。把下面这段整个复制给你的 AI，它能照着写。

## 复制这段

```
帮我给 mailbox-kit 写一层适配，让信箱里的新消息能被叫醒到这个会话里。

仓库：https://gitee.com/copyme/mailbox-kit
先读 adapters/dsh-engine.example.js，那是 DeepSeek Harness 的写法，照着改。

我这边的引擎是：<名字和版本，比如 Claude Code / Cursor / 自己写的 Node 服务>
我是怎么起它的：<命令行 / 插件 / 进程内调用>

你只需要做三件事：
1. 拿到「正在跑的那个会话」——不同引擎的拿法不一样，先在你的宿主里找有没有现成的会话管理接口。
2. 把一段文字塞进去，让它当成用户说的话被处理。
3. 塞完确认一下它是真在处理，不是排队。

别改核心那五个文件（src/ 下面），只在适配层里写。
写完告诉我三件事：会话从哪拿的、消息用什么对象塞的、怎么确认它真醒了。
```

## 它必须回答的三个问题

不管什么引擎，都绕不开这三步。你拿这三个问题去考它，答不上来的就是没写对：

1. **会话从哪拿？** 是有一个 `sessionController` 之类的接口，还是一个全局变量，还是你得自己维护一个列表？
2. **消息用什么形状塞？** 是纯字符串，还是要 `{ role, content }`，还是要有 `id`、`source` 这些字段？
3. **怎么确认它真在处理？** 塞完立刻返回算成功？还是要看状态从 idle 变 running？

## 验证：三条

写完别急着信，跑这三条。

**一、写一条信，看它有没有投出去。**

```bash
echo '- [ ] 09:00 pc→phone：适配层测试，收到回一句' >> ~/Sync/notes/inbox-pc.md
```

盯着终端，十几秒内该出现一行 `投了 1 条`。

**二、看它会话里有没有真的出现那句话。**

日志写着「投了」，不等于 AI 真看见了。去会话里翻一眼，看到那句话才算。

**三、把定时器拆了，看它报不报。**

冒烟脚本就是干这个的：

```bash
node test/smoke.mjs <你的适配层文件绝对路径>
```

退出码 0 是过了。但别只信「过」——**复制一份，故意删掉一个 import 再跑**，它必须报错。报不出来，说明这个脚本是假通过，什么都验不了。

## 三个坑，都踩过

**拿错对象。** 很多引擎有 `agents.get()` 和 `sessionController.resolveAgent()` 两套，前者拿到的东西没有 `followup`。报错长这样：`TypeError: agent.followup is not a function`。看宿主源码，别猜。

**热重载会跑第二遍 apply。** 插件热重载时 `apply()` 会在同一个进程里再跑一次，里面没清的 `setTimeout` 会把第二个守护拉起来，两个 watcher 抢同一份文件。句柄挂到 `globalThis`，新 apply 开头先 `clearTimeout`。

**`node --check` 过了不等于能跑。** 它只查语法。漏一个 import、错一个函数名，要等定时器响第一声才炸。所以才有那个冒烟脚本。

## 写完之后

把它挂上去、重启引擎、按上面三条验一遍。全过了，再回来改你自己那份 `mailbox.config.json`，把 `adapter` 指过去。
