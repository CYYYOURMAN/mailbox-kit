# 核心与配置


这七样少一样，别人拿去就会出事：

| 事 | 为什么 |
| --- | --- |
| 原子读 | 同步盘是「写临时文件再改名」，读到的可能是半截。内容非空且字节数对得上才算读全。 |
| 指纹去重 | 同一句话不能投两次。指纹存盘，重启不重投。 |
| 冲突文件扫描 | 两边同时写同一份会被同步工具改名成 `inbox-pc.sync-conflict-20261109-162710-XXXX.md`。不扫就是丢信。 |
| 防抖 + 最小间隔 | 一次保存会触发好几个事件。攒三秒再读，两次投递至少隔五秒。 |
| 失败撤指纹重投 | 引擎没起来时投不出去，不能算已读。撤掉指纹，下轮再来，满三次放弃并报出来。 |
| 静默时段攒批 | 半夜不响，白天一次补。 |
| 一行一轮日志 | 出问题只有日志能救命。 |
| 首跑只报一次汇总 | 新装的人手上要是有旧信，一条不响等于全丢；逐条吵又刷屏。投一条「积压 N 条」最稳。 |
| 单实例锁 | 两个进程盯同一个信箱会互相抢指纹、吞对方的信。锁里写 pid 加启动时间，死的能接管。 |
| 附件只报大小 | 文件本来就在同步盘里，核心报「在不在一级、多大」，不复制、不传输。 |


## 配置项

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `dir` | 必填 | 信箱目录 |
| `self` | 必填 | 我叫什么。按前缀扫时，跳过自己写的那份 |
| `read` | 无 | 直接写死读哪几份，如 `["信箱-手机.md"]`。文件名不守 `inbox-` 约定时用它；写死的文件旁边冒出冲突文件也会一起读 |
| `prefix` / `ext` | `inbox-` / `.md` | 文件名规则 |
| `seenPath` | `dir/.mailbox-seen-<self>.json` | 指纹库落盘位置 |
| `logPath` | 无 | 不填就不写日志 |
| `debounceMs` | `3000` | 文件变动后等多久再读 |
| `minGapMs` | `5000` | 两次投递最小间隔 |
| `pollMs` | `300000` | 兜底轮询（目录盯不上时全靠它） |
| `quietFrom` / `quietTo` | `0` / `8` | 静默时段。写 `"00:30"` / `"08:30"` 是分钟粒度，写 `0` / `8` 是整点；两边相等表示不静默，跨午夜也对 |
| `maxRetries` | `3` | 投递失败重试几次 |
| `firstRunSilent` | `true` | 首跑扫到积压时不逐条叫醒，只投一条「积压 N 条」的汇总；设成 `false` 就照常一条条投 |
| `lockPath` | 配置文件旁边 `mailboxd.lock` | 单实例锁位置，只给命令行守护用 |


## 事件

- `letters` `{ letters, ack, nack }` —— 有新信。返回 `true` 或调 `ack()` 算成功，抛错或 `nack()` 算失败。
- `delivered` `letters` —— 投成功。
- `failed` `{ letters, why, gaveUp }` —— 投失败。
- `error` —— 轮次异常。
