# mailbox-kit

**两个地方下载，哪个快用哪个：**
- GitHub：https://github.com/CYYYOURMAN/mailbox-kit
- Gitee（国内）：https://gitee.com/copyme/mailbox-kit

两个进程之间传话，用几份 Markdown 文件当信箱，用一个小适配层把人叫醒。

没有服务端，没有端口，没有认证，没有数据库。信箱就是文本文件，扔进任何同步盘（Syncthing、iCloud、OneDrive、git）都能用。核心不认识任何引擎，换引擎只换 `adapters/` 里那几十行。

```
说话的人 ──写──▶ 信箱-alice.md ┐
                               ├──▶ 核心（盯目录、去重、攒批、重试）──▶ wake() ──▶ 被叫醒的人
说话的人 ──写──▶ 信箱-bob.md   ┘
```

> 想看真跑起来的样子：**[案例：两台机器，两个 AI，互相叫醒](docs/两台机器两个AI.md)** —— 从零搭通的全过程，含今天量出来的数和踩过的坑。

## 为什么做这个

因为我一个人用着两个 AI，一个在电脑上，一个在手机上。

它们互相不知道对面干了什么。电脑上那个改完代码，手机上那个不知道；手机上那个跑完采集，电脑上那个也不知道。全靠我在中间转话：复制一段、贴过去、再解释一遍前因。一天下来，转话比干活还累。

我不是想要一个「多智能体框架」。我只想少转两句话。

试过让它们走服务端，要开端口、要认证、要个常驻进程；试过让它们连同一个账号，两边模型不一样，接不上。最后发现手上已经有一个东西两边都能碰：**一个同步文件夹。**

于是就成了这样：几个 md 文件当信箱，谁写完扔进去，对面几秒后自己就看见了。

它解决的不是「AI 不够聪明」，是「AI 坐在两个房间里，互相听不见」。要更细的动机和取舍，见 [它真正解决的是什么](docs/它真正解决的是什么.md)。

## 三层：文件、守护、窗口

**文件**是底。几个 md，躺在同步目录里，谁都能看、能改、能版本管理。这一层不需要任何程序。

**守护**是中间。一个几十行的循环：盯目录，看见自己该读的那份有新行，去重、攒批、叫醒。没有它，你得自己隔一会儿去翻一次——能用，只是慢。

**窗口**是上面。网页（`--ui`），把文件摆成一张表，加两个按钮。它只绑 `127.0.0.1`，关掉不影响任何事。

所以：**不开网页也能用，不装单文件也能用。** 最少的用法是三个动作——写一行、跑一次、读对面那份。其余都是让这三件事顺手一点的。

## 能跑在哪

核心是纯 JS、零依赖，**有 Node 18 以上的地方都能跑**：Windows、macOS、各种 Linux、树莓派、群晖、Docker、安卓的 Termux。不要求同一家系统，也不要求同一个网络——只要那个同步文件夹两边都够得着。

真跑过的：Windows、Linux（另一台机器上的 proot 环境）、安卓 Termux（真机装过、跑过、重启验过）。macOS 那边只有弹气泡那段代码写了没上真机。

**跟平台绑死的不是核心，是「叫醒」。** 每个 AI 引擎的适配层要单独写——它得知道怎么把一段文字塞进那个引擎的会话里，三十行上下。信箱本身换引擎不用改。

## 装

**第一次来，别读这篇，直接看 [十分钟上手：从零到两边说上话](docs/十分钟上手.md)**——手把手八步，每步都给命令和「你会看到什么」，做完两台机器就说上话了。

想自己控制每一步，最短那条路是三条命令：

```bash
git clone https://gitee.com/copyme/mailbox-kit.git
cd mailbox-kit
node bin/mailboxd.js --setup
```

`--setup` 一路问几个问题，最后写成一个 `mailbox.config.json`，然后 `node bin/mailboxd.js --config mailbox.config.json` 就转起来了。

不想装依赖、不想 clone：下 `release/` 里那个单文件，`node mailboxd-0.1.0.mjs`，一样用。

**别的装法**（Windows 双击、单文件、安卓 Termux、网页、问答式配置、文件名不按「前缀+自己」拼）都在 [装法与配置](docs/装法与配置.md)。安卓有单独一份，带真机截图和七步：**[安卓上装](docs/安卓上装.md)**。

## 用

**一、约定文件名。** 谁写的写在文件名上，读者只读别人的那份：

```
notes/
  信箱-alice.md    ← alice 写
  信箱-bob.md      ← bob 写
```

正文每条形如：

```markdown
- [ ] 16:55 下午三点那个会挪到四点，别忘带本子。
- [x] 16:40 昨天那份文件我放你桌面了。
```

`- [ ]` 是没办，`- [x]` 是办完。续行缩进两格。时间可写可不写，核心不解析时间。

要带附件，正文里单写一行 `附件:`，路径按信箱目录算：

```markdown
- [ ] 17:20 这张图你看下
  附件: 附件/截图.png
```

路径必须落在信箱目录里面。核心只报「在不在、多大」，不搬文件。

**二、谁办完谁标。** 允许把对方那条的 `[ ]` 改成 `[x]`，行末加「已办 HH:MM」。除此之外一个字都不许动——正文、时间、方向、缩进都不许碰（缩进会被当续行，指纹一变就重投）。标完拿备份做一遍 diff 核，只有方括号那一格和行末那几个字变了才算对。

不标的话，办过的条目会一直挂在主文件里，归档一碰到就被拦住。这条是踩出来的，不是想出来的。

**三、跑起来。**

```js
import { createMailbox, formatLetters } from 'mailbox-kit';

const box = createMailbox({
  dir: './notes',
  self: 'bob',            // 我叫 bob，就不读 信箱-bob.md
});

box.on('letters', async ({ letters, ack, nack }) => {
  try {
    await 我的叫醒方式(formatLetters(letters));
    ack();                // 投成功才记指纹
  } catch (err) {
    nack(err.message);    // 失败不记，下次重投，满三次放弃
  }
});

await box.start();
```

**四、写适配层。** 只有一件事：把一批信变成「人被叫醒了」。

```js
export function myAdapter() {
  return async function wake(letters) {
    // 发 HTTP、弹窗、塞进会话、喊喇叭，随你
  };
}
```

自带两个：`adapters/stdout.js` 打印，`adapters/balloon.js` 桌面气泡（Windows/macOS/Linux）。真接进一个 AI 引擎的完整例子在 `adapters/dsh-engine.example.js`，注释里写着三个必踩的坑。

配置项、事件、核心到底管哪些、附件怎么核，见 [核心与配置](docs/核心与配置.md)。

## 几件踩过的坑

1. **两边同时写同一份文件，必撞冲突。** 同步盘会把其中一份顶进 `xxx.sync-conflict-日期-随机.md`，读端不认这个名字，信就静默丢了。按写者分文件治得住「正文追加」那一半；标 `[x]` 得改对方那份，撞是常数，不是意外——所以读端必须扫冲突文件，把它当常态。
2. **`node --check` 过了不等于能跑。** 它只查语法。漏一个 import、错一个函数名，要等定时器响第一声才炸。写个冒烟脚本：假 ctx 跑 `apply()`，再把每个定时器手动拨响一次。
3. **验证要验「抓得住」。** 测试全绿不等于测试有用。故意弄坏一处（删一个 import、把阈值改到不可能），看它报不报。假通过比没验更危险。

其余几条（热重载起第二个守护、`?v=` 只重载入口、同步盘读到半截、`pkill` 清不干净）在 [踩过的坑](docs/踩过的坑.md) 里。

## 安全边界：管什么、不管什么

**管四条：**

- 网页只绑 `127.0.0.1`，不接外网。
- 每份信箱只有一个人能写（文件名定方向）。谁该写、谁不该写，是物理约束，不是靠自觉。
- 数据不上传。没有服务器，没有云同步服务是它自己的。
- 令牌最小权限（如果要接 GitHub issue 这类，只给那一项）。

**不管五条：**

- 没有登录，没有审计。谁能读那个同步目录，谁就能读全部信。
- 落盘明文。别往信箱里塞密码、密钥。
- 不防内部人。它假定两台机器的主人是同一个人（或至少互相信任）。
- 同步工具本身要信得过。Syncthing、iCloud 怎么配对、谁有权限，那是另一套系统的事。
- 不保证送达。它尽力投，投不进去会记日志，但没有回执确认那一层。

它能省掉服务器，代价是把信任搬到自己机器上。
