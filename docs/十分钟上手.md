# 十分钟上手：从零到两边说上话

## 让 AI 帮你装

懒得自己走，就把下面这段整个复制给你的 AI（DeepSeek、ChatGPT 都行）：

```
帮我在两台机器上装 mailbox-kit。
仓库：https://gitee.com/copyme/mailbox-kit
照 docs/十分钟上手.md 一步一步来，别跳步，别改命令。
我这台是：<系统，比如 Windows 11>，同步盘目录：<比如 <你的用户名>\Sync\notes>，
这台机器叫：<比如 pc>，对面叫：<比如 phone>。
每跑完一步，把输出贴给我看；要我自己动手的，停下来告诉我点哪里。
```

它替不了你的三件事：装 Node、装同步盘并配对、在手机上敲第一行命令。

这份是手把手。不谈原理，只按顺序做。做完你会有一个能用的信箱，和一台隔着网络的另一台机器说上话。

全程两条命令、一个配置文件、一个网页。不需要服务器，不需要域名，不需要注册任何账号。

---

## 第 0 步：确认有 Node

```bash
node -v
```

看到 `v18` 或更高就行。没有就去 [nodejs.org](https://nodejs.org) 装一个，一路下一步。

Windows 上命令提示符、PowerShell 都行。安卓要 Termux，看 [安卓上装](安卓上装.md)。

---

## 第 1 步：把东西拿到本地

```bash
git clone https://gitee.com/copyme/mailbox-kit.git
cd mailbox-kit
```

没有 git 也行：打开 https://gitee.com/copyme/mailbox-kit ，点右上角「克隆/下载」→「下载 ZIP」，解压，进那个目录。

---

## 第 2 步：建一个信箱目录

这一步在**你的同步盘**里做。Syncthing、iCloud、OneDrive、坚果云，随便哪个，只要另一台机器也同步同一个目录。

```bash
mkdir -p ~/Sync/notes
```

Windows 上是 `mkdir %USERPROFILE%\Sync\notes`，或者直接在资源管理器里建。

记住这个路径，下一步要用。

**为什么非得是同步盘**：这台机器写进去的东西，得自己跑到另一台机器上去。同步盘干的就是这件事。

---

## 第 3 步：跑配置问答

```bash
node bin/mailboxd.js --setup
```

会连着问你几个问题，一路回车用默认值也行，只有第一问必须填：

一共问五句：

| 问什么 | 填什么 | 说明 |
|---|---|---|
| 信箱目录 | `~/Sync/notes` 的完整路径 | 必须填，回车会退出 |
| 我叫什么 | `pc` | 短一点，别用中文和空格 |
| 对面叫什么 | `phone` | 另一台机器上填反过来的 |
| 文件名前缀 | 直接回车 | 它会看你目录里已有的文件自己猜；空目录猜不出，用默认 `inbox-` |
| 配置写到哪 | 直接回车 | 默认跟信箱目录同级 |

后缀 `.md`、读哪几份，这两样不问，按「前缀+对面+后缀」自己算出来。

跑完它会打印：

```
写好了：~/Sync/notes/../mailbox.config.json
```

配置文件名是 `mailbox.config.json`，和信箱目录同级。

**两个名字必须一正一反。** 你这边 `自己=pc 对面=phone`，那边就得 `自己=phone 对面=pc`。填成一样的，两边都读不到对方。

---

## 第 4 步：起来看看

```bash
node bin/mailboxd.js --config mailbox.config.json --ui
```

你会看到类似：

```
信箱守护起来了：~/Sync/notes（自己=pc）
网页：http://127.0.0.1:7654/?k=<口令>
（这个地址带口令，别贴出去。只在本机能开。）
```

复制那行地址（**连 `?k=` 一起**），粘进浏览器。

看到一张空表，上面一个输入框、一个「写进去」按钮。这就是全部界面。

---

## 第 5 步：写第一封信

在网页那个框里写一句，比如：

```
我这边的服务起来了，你那边怎么样
```

点「写进去」。刷新一下，上面多出一条绿边的：`19:32 · pc（我）`。

右边有个「标已办」——那是对自己写的条用的，先别点。

**同时，你的信箱目录里多了一个文件**（目录原本是空的，前缀用了默认的 inbox-）：

```bash
cat ~/Sync/notes/inbox-pc.md
```

```markdown
- [ ] 19:32 pc→对面：我这边的服务起来了，你那边怎么样
```

这就是全部。没有数据库，没有队列，就是一个文本文件多了一行。

---

## 第 6 步：另一台机器上照做

在那台机器上重复第 1 到第 4 步，只有第 3 步的两个名字反过来：

- 这边：自己 `phone`，对面 `pc`
- 信箱目录：指向同一个同步目录

等同步过去（几秒到十几秒），它那边的网页上会出现你写的那条，蓝边的，标着 `pc`。

对方的条只给一个「写回执」按钮——点了会往**它自己那份**文件里加一行，不碰你的文件。

它写了回执，你这边几秒后就能看见。

**到这一步，两边已经说上话了。** 后面都是让它自动醒，不用你盯。

---

## 第 7 步：接进你的 AI（可选但有意义的一步）

前面六步做完，信能通，但**没有人被叫醒**——你得自己隔一会儿去翻。

要让 AI 自己醒，得写一个适配层。核心只要求它做一件事：

```js
export function myAdapter() {
  return async function wake(letters) {
    // letters 是一批信，长这样：
    // [{ writer: 'phone', body: '19:32 ...', attach: [] }]
    // 你要做的：把这些字塞进那个 AI 的会话里，让它看见
  };
}
```

`letters` 到手、塞进会话、调用返回——三步。塞不进去就抛错，核心会重投，满三次放弃。

**为什么这一步不能替你写**：每个 AI 引擎的接口都不一样，「怎么把一段文字塞进正在跑的会话」这件事只有那个引擎知道。写这份文档的人在这上面栽过：`ctx.agents.get()` 拿到的东西没有 `followup` 方法，正确的是 `ctx.get('sessionController').resolveAgent(会话号)`。

`adapters/dsh-engine.example.js` 是一个完整的例子（DeepSeek Harness），三十行，注释里写着三个必踩的坑。别的引擎照这个结构改。

---

## 第 8 步：出问题看哪儿

出问题先看这三个地方，按顺序：

1. **网页打不开**——看终端里那行地址是不是带 `?k=`。端口 7654 被占会自动往后找（最多试到 7753），实际地址看终端打的那行，别自己猜。
2. **信不出现**——`cat` 一下你那份 md，看那行到底进去没有。文件里有、网页里没有，是读端的问题；文件里就没有，是写端的问题。
3. **对面收不到**——先看同步盘有没有把那行同步过去（打开对面那台机器的目录看一眼）。同步盘没过去，跟这个工具一点关系都没有。

**想看日志就加 `--log`**，不加的话只在终端上打几行、不落盘：

```bash
node bin/mailboxd.js --config mailbox.config.json --ui --log run.log
tail -f run.log
```

```
[2026-01-01 09:00:00] 启动 目录=~/Sync/notes 自己=pc
[2026-01-01 09:00:00] 盯上了目录 ~/Sync/notes
[2026-01-01 09:00:05] 投了 1 条 来=信箱-phone 首条：09:00 phone→pc：...
[2026-01-01 09:00:06] 投递确认（三分钟）会话=session-… status=running
```

时间是本机时间。看到「投了」就是真递进去了。什么都没打印，说明它没看见新行——去查同步。

---

## 做完这些，你手上有什么

- 两个文本文件，在你自己的同步目录里
- 一个几十行的守护进程，盯着它们
- 一个本地网页，能看能写
- 两台机器之间，五秒到十几秒的传话

没有账号，没有服务器，没有月度账单。想停就 `Ctrl+C`，文件还在，明天接着用。
